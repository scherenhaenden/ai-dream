# RAG integration proposals

> **Status: proposals, not implemented features.** These documents come from a static review of the code in this repository and in the separate `my-rag` project (nothing was executed). Like [ROADMAP.md](../../../ROADMAP.md), they record planned work. Statements marked **(verify)** have not been confirmed in code.

## Goal

Stop re-implementing the same LLM-provider and RAG code in every program. `ai-dream` becomes the single home for it, absorbing what `my-rag` (Atlas) does that `ai-dream` does not, and adding SQLite sources, drag-and-drop ingestion and per-model context-window configuration.

## Key findings in one place

1. **Remote providers are listed, not used.** `ProviderConnections` can store and test them, but nothing sends chat, embedding or rerank requests through them. `my-rag` has those clients but with weaker security (no keyring, no SSRF guard).
2. **No SQLite support and no drag-and-drop exist in `ai-dream`.** The knowledge index is lexical-only and capped at 80,000 characters in total. Upload limits (5 MiB knowledge, 32 MiB artifacts) are too small for databases.
3. **Remote embeddings leak data by default in `my-rag`.** Indexing a SQLite file sends every row to the embedding provider with no confirmation. This must not be copied; see the privacy section in document 02.
4. **Context window is a load option only.** There is no distinction between trained maximum, configured window and usable prompt budget, no setting for remote models, and prompt limits are fixed character counts.

## Suggested order of work

1. Shared provider core (document 01, step 1). It unblocks embeddings, rerank and remote context settings.
2. SQLite as a source with exact read-only SQL tools, no embeddings (document 02, phases 0-1), plus the drag-and-drop UI (phase 2).
3. Context window resolution and `ContextBudget` (document 03, tasks C1-C5).
4. Row-level retrieval and vectors, other file formats.
