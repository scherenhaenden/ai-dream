# Design prototype parity map

The screen names below refer to the React reference in this directory. Routes point to the current production Angular app in `web/src/app/app.routes.ts`. They are related concepts, not shared screens: the reference has no connection to Angular or the local service. Enabled reference interactions are limited to navigation and local presentation/sample state; they do not persist data or call Angular or the local service.

| Design Unit | Angular navigation label | Angular route | Production capability and parity boundary |
|---|---|---|---|
| Chat | Chat | `/chat` | Local API backed chat, saved conversations, model selection, generation settings and knowledge toggle. The prototype's messages, runtime indicators, artifacts and responses are examples. |
| Agent | Agent | `/agent` | Sends prompts to a locally selected model and uses the fixed read-only tool registry to inspect local hardware, models, and runtime state. Each turn is bounded to at most four tool calls and 45 seconds. The prototype shows the intended entry point only: its conversation is non-interactive and its prompt/send controls are disabled. |
| Models Library | Models | `/models` | Model Studio backed by local model and runtime APIs. Do not assume prototype inventory, benchmark scores, or model actions match this device. |
| Model Hubs | Model Hubs | `/hub` | Searches Hugging Face GGUF repositories and can start local downloads. Prototype results and progress are illustrative. |
| Hardware Topology | Hardware | `/hardware` | Displays hardware reported by the local API. Prototype topology and utilization values are sample data. |
| Load Model Placement | Load Model (Placement) | `/load-model` | Runtime Manager selects a model/runtime and configures device placement and load settings. Prototype placement outcomes are not executed. This route resolves to the same Angular `RuntimePage` component as `/runtime`. |
| Runtime Manager (formerly Providers & Runtimes) | Runtime Manager | `/runtime` | Registers/probes local llama-server executables, configures placement and supported load options, and loads/unloads models. The static reference shows this workflow with unavailable state and disabled preview controls; it does not invent a runtime inventory or execute actions. This route resolves to the same Angular `RuntimePage` component as `/load-model`. |
| Local API Server | Local API | `/local-api` | Checks the Settings-configured loopback API with `GET /api/health` and documents seven GET routes. Listed route availability follows that health check; routes are not probed individually. It does not start, stop, configure, expose external client sessions, or provide an OpenAI-compatible `/v1` server. The reference shows sample address/health details and disables refresh. |
| Knowledge / Local Search | Knowledge (RAG) | `/knowledge` | Adds, searches, and removes local documents through the API. Search is SQLite FTS5 lexical matching (up to 16 words, 256-character query), with no embeddings or semantic RAG. Accepts TXT, Markdown, and text-based PDF up to 5 MiB; extraction is limited to 40,000 characters per document, 80,000 total, and 100 documents. Scanned PDFs are not OCR-processed. Reference documents/results are examples; its enabled search control only displays a synthetic sample match, and upload is not connected to the API. |
| Tools & Permissions | Tools & Permissions | `/tools-permissions` | Reads tool names, descriptions, argument schemas, policy, and turn limits from `GET /api/agent/tools`. The current contract has four read-only tools and excludes shell, filesystem-write, and network-fetch tools. Current bounds are 4 tool calls, 45 seconds, and 12,000 output characters per turn. The reference registry and bounds are labeled examples, refresh is disabled, and no permission toggles are exposed. |
| Downloads | Downloads | `/downloads` | Shows local transfer queue state and supports cancellation. Prototype transfer names, percentages, and completion states are samples. |
| Logs & Traces | Logs & Traces | `/logs` | Requests bounded raw output snapshots from supported runtime backends and separate local application diagnostic events. Runtime output can be unsupported or unavailable when no capturable llama-server process/source is active. Prototype events and traces are not live telemetry. |
| Settings | Settings | `/settings` | Stores the loopback API base URL in browser storage and checks `GET /api/health`; configures model-profile precedence, keep-last-model-loaded, read-only managed-model/config/data paths, default backend/runtime, and capability-supported placement/load defaults. The prototype values and health state are unavailable/static; only capabilities advertised by the selected runtime are valid options. |

All 13 design Units map to the 13 Angular navigation entries and their configured routes. The labels match the production navigation where concepts are shared; “Models Library,” “Hardware Topology,” “Local API Server,” and “Knowledge / Local Search” are descriptive design names for Angular’s “Models,” “Hardware,” “Local API,” and “Knowledge (RAG).” `/load-model` is a separately registered route, not a redirect alias; both it and `/runtime` load the same Angular `RuntimePage` component. Thus the navigation count is 13/13, while those two entries do not represent distinct Angular page implementations.

## Parity rule

Treat every value, connection badge, model/provider, log line, confirmation, and resulting state inside the React reference as mock content unless it is explicitly labeled as explanatory static copy. Backend-dependent actions are either disabled or explicitly simulated with sample content; for example, the Knowledge search control displays a synthetic match. Enabled prototype-only interactions never call or persist to the production service. The Angular app and its local API are the sources of truth for supported operations and live device data. Source mapping and token calculations do not constitute rendered UX approval: browser checks for responsive layouts, keyboard/focus behavior, rendered contrast, and screen-reader semantics remain required before claiming full readiness.
